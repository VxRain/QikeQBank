## 2. P0

### FE-P0-02 删除可恢复（回收站 / 撤销）

**问题**
- `questions_remove` 写墓碑后直接 `DELETE`；`delete_log` 只存实体 id/时间，误删不可恢复。
- 删题库会级联删除其下试题、流水、复习状态；确认弹窗是唯一保护。批量删除逐条执行，中途失败无回滚、无失败清单。

**要做**
- 推荐新增归档表（`deleted_questions`：完整题目 JSON + bank_id + deleted_at + actor；删库时同时归档 `banks` 行与其下题目）。`*_remove` 在同一事务里先归档再删除，归档失败整体回滚。
- 新增 `questions_restore` / `banks_restore`：恢复用新 `updated_at`，并处理墓碑与同步复活的冲突规则。
- 前端：删除后 toast 提供 5–10 秒「撤销」；`List.vue` / `Banks.vue` 增加「最近删除」入口（恢复 / 彻底删除 / 清空）；批量删除改单次事务 + 逐项结果。
- **口径必须先定**：作答流水 / 复习状态是否随题恢复（当前外键级联会一并删除）。只承诺恢复题目内容时，UI 必须写清。
- 多设备语义先定义：「删除后恢复」在对端仍持墓碑时的期望结果，否则一恢复又被删。

**验收**：10 秒内可撤销且（按拍板口径）状态一致恢复；「最近删除」可查看/恢复/彻底删除；批量部分失败能逐项看到结果。

### FE-P0-12 抽题配额与材料题统计口径

**问题**
- 多选题型时按 `ceil(limit / types.length)` 平摊：某题型不足不补足，实际题量少于所选，「全部」也偏题多的题型。
- `practice_pool` 是 `ORDER BY RANDOM()`：不排除刚做过的题，不按错题/难度/掌握度加权。
- 材料题按母题请求、按子题展开：选「5 题」可能变成 15 个作答项；`review_state` 每母题一张卡，但 `reviewedCount` 按子题累加，待复习数与本轮题数对不上。
- 模考「答对」取得分率 ≥ 60%，练习「全对才算对」，口径不同但 UI 未解释。

**要做**
- `practice_pool` 接受 `types: []`、`excludeRecentHours`、`strategy`，一次查询完成多题型抽样；返回 `{items, requested, returned, poolTotal}`。配额先按题型目标抽，不足向其他题型二次分配，前端不再循环调用。
- 可选排除最近 N 小时已作答（避免同一轮连着抽到刚做过的）。
- 材料题：短期先统一文案「N 张卡 · M 问」，进度/剩余按同一口径；中期再评估「整题一张卡一次评分」vs「子题独立成卡」（两者都要先改 schema/契约）。
- 统计页与成绩单明确标注三类口径不可混算：练习全对率、模考得分率（≥60%）、复习自评。

**验收**：请求题量与实际返回一致（不足时明确提示，不静默缩水）；材料题「张数 / 问数」在进度、待复习、统计三处口径一致；三类正确率在 UI 上有口径说明。

- 验收：主链路本地一键运行；答题状态机回归有自动化覆盖。

### FE-ARCH-09 E2E 迁 `@playwright/test`

**动机**：当前 `tools/e2e-frontend.mjs` 是手写 runner + 手调等待，绿是「等待恰好配对」的产物 —— 任何新用例少写一个谓词就重新 flaky，守门手段只有人肉 review。框架的自动重试 + `webServer` + `--shard` + trace 能把这类风险从「靠人写对」变成「机制保证」。

| 能力 | 现在（手写） | 迁移后 |
|---|---|---|
| dev server | 脚本内 spawn/poll/复用 | `webServer` + `reuseExistingServer` |
| 分模块 / 只跑改动 / 分片 | 自建 `MODULES` + 位置参数 + `--changed` | `test.describe` / `--only-changed` / `--shard` |
| 等待 | 自写 `waitText` / `waitUntil` / `flush` | `expect(locator)` 自动重试 |
| 失败诊断 | 失败详情字符串 | trace viewer + HTML 报告 |

**前置隐患**：`@playwright/test@1.64.1` 已存在于 `node_modules`（传递依赖）但 `package.json` 未声明 —— 干净安装 / CI 上 e2e 必然跑不起来（`loadPlaywright()` 退到 npx 缓存）。迁移时必须显式进 `devDependencies`，并处理浏览器版本（当前靠 `findChromium()` 回退，应改为 `npx playwright install chromium` 或固定版本）。

**步骤**：① `pnpm add -D @playwright/test` + `playwright.config.js`（`webServer` 指 vite，`projects` 按 11 模块切）；② 现有断言按模块搬进 `tests/e2e/*.spec.mjs`，`ok(name, cond)` → `expect(...)`；③ 每搬一个模块跑新旧对照，断言数与结论必须一致；④ 全绿后删旧 runner，脚本改 `playwright test`；⑤ 模块名以 `MODULE_IDS` / `MODULE_BASELINE` / `package.json` 脚本为准（`--list` 打印），不往文档里抄。

**验收**：各模块可 `--project` 独立跑且断言总数不降；全量耗时 ≤ 迁移前（~26s）；连续 10 次 0 flaky；干净安装可直接跑；失败产出 trace 可回放。

- **FE-P2-07 题库分享 / 导入 / 模板市场**：交换格式需在数据保全方案定案后定义（旧 JSON 导入导出已移除）；先保证导入安全（预览、校验、可撤销）。

- **FE-P2-09 题库层级 / 文件夹**：题库分组/文件夹/排序，适配「一个学科多个题库」。与 FE-P2-01 二选一或组合，先调研再动。
- **FE-P2-10 多端冲突可视化**：现在只有「以云端为准 N 条」计数；需冲突列表 + 字段级对比 + 选择性保留，依赖同步契约扩展。
- **FE-P2-11 会话快照 `extra` 的运行期校验**：`src/stores/session.ts` 的 `normalizeSnapshot` 只用 `isPlainObject` 判 `extra`，不校验内部字段。受污染快照（如 `extra: { flaggedKeys: 'oops' }`）能过归一化，随后 `Practice.vue` 的 `flaggedKeys.filter(...)` 抛 `TypeError`。修法：对 `flaggedKeys` 补 `Array.isArray` + `filter(typeof === 'string')`，与同文件 `keys` / `wrongKeys` 的写法对齐；同类风险点还有 `answers`（`Record<string, unknown>`，下游按字符串读）。**这是既有缺陷，不是类型迁移引入的漂移。**
- **FE-P2-12 `strictNullChecks` 评估**：`strict:false` 下 `a.b.c` 里 `b` 不存在也放行，而 undefined 访问是这类客户端最高频的崩溃来源（见 FE-P2-11）。先跑一遍 `strictNullChecks:true` 统计条数与分布，再决定是否复用棘轮机制按文件上闸。

## 8. 未达成的验收指标（达成就删）

- 首页到开始刷题 ≤ 2 次点击；首次启动 3 分钟内完成第一题。
- 误删 1 分钟内可恢复（依赖 FE-P0-02）；备份新鲜度 ≤ 7 天且有提示（口径随数据保全定）。
- 1000 题库下列表翻页 < 300ms（本地）。
- 多题型抽题实际数量 = 请求数量，或明确提示不足（依赖 FE-P0-12）。
